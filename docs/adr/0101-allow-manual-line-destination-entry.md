# Allow manual LINE Destination entry

ADR 0009 restricted LINE Destinations to signature-verified webhook discovery so that arbitrary destination IDs are never treated as trusted contacts. In practice an Organization's LINE Connection, and therefore its webhook, is not always configured yet, and a member's LINE user ID may already be known from a prior process. Requiring a working webhook before any Recipient Profile can be reached leaves an Organization with no path to configure LINE delivery at all during that gap.

Mail Automation now lets an Owner, Admin, or Operator manually enter or correct the LINE Destination linked to one Recipient Profile, in addition to webhook discovery. A manually entered LINE Destination still requires an active LINE Connection, is still scoped to it, and is recorded with `source = manual` rather than `webhook` so it remains distinguishable in the GUI and in audit history from a destination the LINE platform itself confirmed. Re-entering a corrected ID for the same Recipient Profile replaces its existing manually entered LINE Destination rather than accumulating stale entries; a webhook-discovered LINE Destination unlinked from a Recipient Profile stays available for reassignment instead of being deleted. A LINE Destination ID already linked to a different Recipient Profile is rejected.

This supersedes the "arbitrary destination IDs are not treated as trusted contacts" posture in ADR 0009 for the manual-entry path specifically; webhook discovery remains the default and the only source that does not depend on an operator correctly transcribing an ID.
