# Use one Google authorization for Organization setup

The Google account authorized during Organization setup becomes both the Automation Inbox and the initial Owner identity. The signed-out application first offers an application-local choice between creating a new Organization and logging into an existing Organization; that choice is not a separate Google authorization. New Organization setup requests the complete Automation Inbox grant in one OAuth round trip, while existing-member login requests the identity-only grant in one separate intent. The two intents are not chained in the normal flow.

The authorized account's display name supplies the editable Organization-name default, and provisioning begins after that name is confirmed without separate Owner email entry or passkey registration. Later management login uses Google identity authentication; Mail Automation does not expose passkey registration or login UI. This supersedes ADRs 0037 and 0089 and the passkey steps in ADRs 0087, 0090, and 0091.
